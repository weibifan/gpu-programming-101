# 第1部分 直觉：大模型是什么

## 1. 大模型 / LLM 到底是什么

### 1.1 一句话：LLM 是一个超大的"下一个词预测器"

把所有花哨的词放一边，大语言模型（Large Language Model，LLM）的骨架只有一句话：

> **给一段前文，输出"下一个词最可能是哪个"。**

你给 ChatGPT 打"今天天气真好，我准备去公园____"，它补上"散步"——就这么简单。你见过的所有"写代码""翻译""聊天"，底层都是**同一个动作在一遍遍重复**：看前文，猜下一个词。

- 训练时：拿海量文本，每句话挖掉最后一个词当"考题"，让模型学"前文 → 下一个词"
- 推理时：给一段前文，模型给出"下一个词的概率分布"，挑一个输出

### 1.2 为什么"预测下一个词"这么强

**因为"会续写"本身就意味着"会理解"。** 要把"今天天气真好，我准备去公园"续得合理，模型必须知道：这句话在讲什么、主语是谁、"公园"是什么东西、"准备去"后面通常跟什么。语义、逻辑、知识、风格——**全都藏在"预测下一个词"这个任务里**。

对 C/Java 程序员，一个贴切类比：**马尔可夫链的超级升级版**。最简单的文本生成是马尔可夫链——只看上一个词决定下一个词，所以记不住长上下文、生成的东西驴唇不对马嘴。LLM 是"看全部前文"的马尔可夫链，而且这个"看"是**参数化的**（几十亿个权重里存着语言规律），不是查一个表。

> 一句话：**LLM 不是被"写"出来的程序，是被"训练"出来的统计模型——训练数据的统计规律就存在权重里。**

### 1.3 自回归生成：一个词一个词地蹦

推理时模型是一个**打字机**，一次蹦一个词：

```
输入：  "今天天气真好，我准备去"
   └─► 模型预测下一个词 → "公园"
拼回去： "今天天气真好，我准备去公园"
   └─► 模型预测下一个词 → "，"
拼回去： "今天天气真好，我准备去公园，"
   └─► ...（循环，直到结束符）
```

自己生成的词不断拼回输入、再预测，这叫**自回归（autoregressive）生成**——"自"= 用自己的输出当输入。

> ⚠️ 这个"一步步蹦"是 05 篇一切性能问题的根源：**prefill**（一次性并行算完整个 prompt 的注意力）还算便宜；**decode**（一次只算一个新词，前面算过的不想重算）→ 引出了 KV cache。读 05 篇 §1.4~§1.5 时你会看到它。

### 1.4 "大"在哪

| 维度 | 小模型（如 nanoChat） | 前沿大模型 |
|---|---|---|
| 参数 | 约 0.3B（12 层 × 768 维） | 数百 B（GPT-4 级） |
| 层数 | 12 | 96+ |
| 训练数据 | 数 GB 文本 | 数万亿 token |

但**"大"不是本质，架构才是**——同样的架构，堆参数就变大。所以这篇文档讲架构，不讲"大"。

### 1.5 为什么是 Transformer，而不是 RNN？

在 Transformer（2017）之前，处理文本的主流是**循环神经网络（RNN）**——它像一条流水线，一个词一个词地处理，把前面所有信息"压缩"进一个隐藏状态往后传：

```
RNN：词1 ──► 状态1 ──► 词2 ──► 状态2 ──► 词3 ...
      把历史"压缩"进一个小状态，逐个往后传
```

两个致命缺点：

1. **不能并行**：第 3 个词必须等前 2 个算完 → 训练慢
2. **记不住长距离**：状态是个小瓶子，塞不下"第 1 句交代的伏笔"到"第 50 句的呼应"

Transformer 换了个思路：**整段序列一次并行处理，任何两个位置之间直接建立联系**。这个"直接联系"就是**注意力（attention）**——也是本篇第 3 节的主角。

> 记住这个动机：**attention 存在，是为了让每个词都能"直接看到"序列里的其他词。** 后面所有复杂设计都围绕这个展开。

# 第2部分 零件：从词到注意力到 block

## 2. 词是怎么变成数字的：token 与 embedding

神经网络只能吃数字。文本进门第一件事就是变成数字。

### 2.1 token：把文本切成小块

先按词/子词把文本切成一串**token**（整数 id）：

```
"今天天气真好"  →  [3132, 4862, 1051, 16863]   （每个数是词表里的一个编号）
```

切法（BPE 等）是第 1 章的事，这里只需知道：**每个 token 是一个整数 id，id 的范围 = 词表大小（vocab_size）**。nanoChat 的词表 32768 个 id。

### 2.2 embedding：查表拿到向量（C 程序员的哈希表）

模型不能拿一个整数"3132"直接算——它需要这个词的**向量表示**。做法是查一张大表：

```
词表 32768 × 向量维度 768
  查"3132" → 一行 768 维向量
```

对 C 程序员，这就是**一张哈希表**：id 是 key，768 维浮点向量是 value，`O(1)` 查出这个词的"语义向量"。这张表叫 **token embedding（wte）**，它的内容是**训练学出来的**——训练结束后，"猫"和"狗"的向量会靠得很近（语义相近），"猫"和"函数"离得远。

```
X = wte(idx)      # [B, T] 的 token id 表 → [B, T, 768] 的向量序列
                  # B=batch, T=序列长度, 768=embedding 维度(记作 d)
```

> 一句话：**embedding = 把离散的 token id 查成稠密向量，语义相近的词向量相近。**

### 2.3 一个必须解决的问题：attention 不分词序

注意力（下一节）是对"序列"做加权汇总，但**它本身不知道词的先后**——把"我打你"和"你打我"调换顺序，注意力看到的"每个位置和其他位置的相关度"完全一样。可词序在语言里至关重要（"打"的对象是谁）。

**结论：位置信息必须显式编码进模型。** 这是 Transformer 家族一个长期主题，两个案例各给一种解法：

- 早期 Transformer：给 embedding **加上**一组正弦/余弦的位置向量（§6.3）
- nanoChat：在注意力内部用**旋转位置编码 RoPE**（§7.3）

现在你只需要记住这个问题存在。

## 3. 注意力：让每个词"看"其他所有词

### 3.1 直觉：加权汇总，"软"查表

先看一个具体需求。预测"她____了，因为太阳很晒"，模型需要知道"____"最可能是"戴帽子"还是"打伞"——这取决于"她"是谁、"太阳很晒"这个原因。也就是说：**每个位置的输出，要根据"其他所有位置"的相关程度汇总出来**。

C 程序员再熟悉不过的类比：**普通的哈希表是"硬"查表，attention 是"软"查表**。

```
哈希表（硬）：  result = table[key]          # 精确命中一个 key
注意力（软）：  result = Σ 权重ᵢ × valueᵢ     # 对每个 key 都算一个"相似度"，
                权重ᵢ = 相似度(query, keyᵢ)   # 然后加权求和
```

"软"意味着：不赌某一个词，而是**按相关程度把一串词的贡献按比例加权**。这就是注意力的全部直觉。

### 3.2 Q / K / V：检索三件套

为了算"相似度"，每个位置的向量要扮演三种角色，靠三个矩阵（权重）投影出来：

| 角色 | 含义 | 通俗类比 | 怎么得到 |
|---|---|---|---|
| **Q**（Query，查询） | "我在找什么" | 检索词 | $Q = XW_q$ |
| **K**（Key，键） | "我有什么标签" | 文档标题 | $K = XW_k$ |
| **V**（Value，值） | "我实际携带的内容" | 文档正文 | $V = XW_v$ |

一个位置的 **Q** 去和所有位置的 **K** 比相似度，得到权重，再按权重把 **V** 加权汇总：

```
"她"的 Q  ←→  "她"的 K / "打"的 K / "伞"的 K / ...
  相似度高的位置给大权重，把这些位置的 V 加权求和 → 就是"她"位置的新表示
```

> 图书馆类比：每个词在书架上放了三张卡——**Q 卡**写"我最近想读什么"，**K 卡**写"我是哪本书、讲什么的标签"，**V 卡**写"书的具体内容"。你拿着 Q 卡去和所有 K 卡比对（找最匹配的书），然后翻开最匹配的书读内容（取 V）。

### 3.3 公式：缩放点积注意力

一行公式，四步拆开。设序列长度 T、维度 d（head 维度记 $d_k$）：

$$Attention(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$

（记号与 附件2 §7 一致：$Q,K,V$ 是三个线性投影，$S$ 是得分矩阵，$P$ 是 softmax 权重，$O$ 是输出。那里手算过这里的**反向**；本篇讲**正向**。）

前两步算出形状 `[T, T]` 的"相关度矩阵"，后两步做加权汇总：

$$S = \frac{QK^\top}{\sqrt{d_k}} \qquad (1)\ \text{打分：query 和每个 key 有多像}$$

$$P = \mathrm{softmax}(S,\ \text{dim}=-1) \qquad (2)\ \text{每行归一化成权重（和为 }1)$$

$$O = P\,V \qquad (3)\ \text{加权求和：按权重混合所有 value}$$

对应到 03 篇：**第 (1) 步 `Q @ K^T` 就是一次矩阵乘**——你在 03 篇手写过 SGEMM，这里的"相关度矩阵"本质就是它在 Transformer 里的现身。FlashAttention（05 篇 §3）优化的正是这个"大矩阵"的带宽问题。

> 一个位置输出：**"我把序列里所有位置的内容，按'我和它有多相关'加权混在一起。"** 这就是注意力的全部。

### 3.4 为什么除以 √d_k

$Q_i \cdot K_j$ 是 $d_k$ 个数的和，$d_k$ 越大，内积的数值通常越大。而 softmax 的输入太大时，概率会变得**过陡**（趋近 one-hot，梯度消失）。除以 $\sqrt{d_k}$ 把内积拉回"单位尺度"——一个常被忽略但必要的细节。

### 3.5 多头注意力：一次不够，多学几套

一个 Q/K/V 只能学**一种**"关注模式"（比如全按字面相关）。但真实文本里，模式很多种：

- 头 A：关注语法关系（"打"的宾语）
- 头 B：关注指代关系（"她"指谁）
- 头 C：关注位置关系（相邻词）
- ……

**多头注意力（Multi-Head Attention）** = 并行学 h 套 Q/K/V，每套关注一种模式，最后拼起来：

```
X [T, d] ──► 拆成 h 份，每份 d/h 维（叫 head_dim）
   head 1: Q₁K₁V₁ → O₁   （关注语法）
   head 2: Q₂K₂V₂ → O₂   （关注指代）
   ...
   head h: QₕKₕVₕ → Oₕ   （关注位置）
   拼回 [T, d] → 再乘一个投影 W_o  → 输出
```

公式（h 个并行的 3.3，拼起来）：

$$MultiHead(Q,K,V) = \mathrm{Concat}(head_1,\ \ldots,\ head_h)\, W_o, \qquad head_i = Attention(QW_i^Q,\ KW_i^K,\ VW_i^V)$$

> 工程真相：多头**几乎不增加参数**（每头维度更小），只是把"算注意力"这件事重复 h 次、各学各的——用很少的代价换来 h 种视角。

## 4. 因果 mask：为什么训练时不能偷看未来

### 4.1 问题：自回归模型训练时，位置 i 不能看到 i 之后的词

回想 §1.3：推理是"一个词一个词蹦"，预测第 i+1 个词时，模型只能看到前 i 个词。但 §3 的注意力是**双向**的——第 i 个位置会去看第 j>i 的位置。

如果训练时不拦住，模型就"偷看答案"了：预测"今天天气真好，我准备去____"时，如果模型能看见正确答案"公园"，它就学会作弊——训练损失会很好看，但推理时（看不到未来）就露馅。

### 4.2 实现：把右上三角填成 -∞

因果 mask 的做法极其朴素：在相关度矩阵上，**把"看未来"的格子填成 -∞**，softmax 后它们就变成 0：

```
相关度 S = Q K^T 是 [T, T] 矩阵，位置 (i,j) = "i 关注 j"
加 mask：
   j ≤ i（看左边/自己）→ 保留
   j > i（看未来）     → 填 -∞
softmax(每行) 后：未来格子的权重 = 0
```

效果：第 i 个位置**只能加权汇总前 i 个位置**——和推理时的"一步步蹦"严格一致。这就是为什么 GPT 叫 **decoder-only**（只有"只往左看"的注意力），而早期 Transformer 还要多一个双向的编码器（§6）。

> 一句话：**因果 mask = 让训练时的可见范围 = 推理时的可见范围**。这是自回归模型正确性的基石。

## 5. 一个 Transformer Block：四件套

上面的注意力是"一块砖"。真实的模型是**一堆 block 堆起来的**，每个 block 由四件套组成：**注意力 + FFN + 残差 + 归一化**。

### 5.1 结构：pre-norm 的两段式

现代 decoder-only 模型（GPT、nanoChat）每个 block 长这样：

```
输入 X
 │
 ▼
Norm(X) ──► 注意力 ──► 结果 + X（残差加）   ← 注意力这半边
 │
 ▼
Norm(X') ──► FFN   ──► 结果 + X'（残差加）  ← FFN 这半边
 │
 ▼
输出，进下一层
```

代码（nanoChat 的 Block，真实源码）：

```python
class Block(nn.Module):
    def __init__(self, config, layer_idx):
        super().__init__()
        self.attn = CausalSelfAttention(config, layer_idx)
        self.mlp   = MLP(config)
    def forward(self, x, ...):
        x = x + self.attn(norm(x), ...)   # 归一化 → 注意力 → 残差加
        x = x + self.mlp(norm(x))         # 归一化 → FFN     → 残差加
        return x
```

**两个半边的分工**：

| 半边 | 干什么 | 类比 |
|---|---|---|
| 注意力 | **跨位置**交换信息（每个词看其他词） | 开全体会，每个人交换情报 |
| FFN | **每个位置各自**做非线性变换 | 会开完，每个人回工位独立思考 |

注意力和 FFN **交替进行**：先"互通有无"，再"各自消化"，如此反复 N 层。这是 Transformer 的固定节奏。

### 5.2 残差连接：每层只学"改多少"

残差连接（residual / skip connection）就是那个 `x +`：本层输出 = 本层结果 + 原输入。

> C 程序员类比：**git 的 diff**。每层不负责"这一层的完整表示是什么"，只负责"相对于上一层，我要改多少"。$x \leftarrow x + \Delta(x)$，$\Delta$ 是这一层的增量。

好处：梯度能顺着残差**跳过所有层**直接回流（$\frac{\partial (x+\Delta)}{\partial x} = 1 + \frac{\partial\Delta}{\partial x}$，梯度不容易消失），所以能堆 96 层都不炸。

### 5.3 归一化（Norm）：把激活值拉回统一尺度

层数深了，激活值会漂移（有的巨大、有的趋零），训练不稳定。归一化把每行激活**重新标准化**（减均值除标准差，再乘一个可学习缩放）。两种主流实现：

| 名称 | 特点 | 谁在用 |
|---|---|---|
| LayerNorm | 减均值、除标准差，有可学习参数 | 早期 Transformer |
| RMSNorm | 只除均方根（免去减均值），可无学习参数 | nanoChat |

> 类比：**归一化 = 洗牌前先把牌理齐**。数据尺度统一，梯度才好走。

### 5.4 FFN（MLP）：每个位置各自的"思考"

FFN 就是一个两层的全连接（你在 04 篇的 MLP 里见过 Linear + ReLU）：

$$FFN(x) = W_2\,\sigma(W_1 x + b_1) + b_2 \qquad \text{（先放大再压缩）}$$

- 中间维度放大到 4 倍（`4 * d`）：给"思考"留空间
- 激活函数 σ 提供非线性——早期用 ReLU/GELU，nanoChat 用 **ReLU²**（§7.3 ③）

> 参数大头其实在 FFN（注意力层和 FFN 层参数约各半）。很多人以为 Transformer = 注意力，其实**一半算力和参数在 FFN**。

### 5.5 组装：一个完整的 decoder-only 模型

把零件串起来，就是一个能跑的最小 LLM（nanoChat 的 GPT 类结构）：

```
token id 序列 [B, T]
  → wte 查表        → [B, T, d]  （§2.2）
  → 位置编码          （§2.3：早期正弦 / nanoChat RoPE）
  → Norm
  → Block 1         （attn + FFN + 残差 + Norm）  ┐
  → Block 2                                        │  N 个 block 堆叠
  → ...                                            │  （nanoChat N=12）
  → Block N                                       ┘
  → Norm
  → lm_head 线性层   → [B, T, 词表大小] = 每个位置"下一个词"的打分
  → softmax         → 下一个词的概率分布（§1.1 的"猜下一个词"）
```

> 可跑版：`code/04_pytorch_gpu/ex22_minigpt.py`（10 万参数不到的玩具 GPT——CPU 上 400 步约 3 秒训完就能生成文字，每个组件都注释了对应本节编号）。

> 整个模型的骨架就三样：**embedding 进出 + N 个 block 堆叠 + 最后投影回词表**。全部组件你已经学完。

# 第3部分 案例：两个完整架构

## 6. 案例1：早期 Transformer（Vaswani 等，2017，"Attention Is All You Need"）

### 6.1 出身：翻译任务 → 编码器-解码器

第一个 Transformer 是**为机器翻译**设计的：输入一种语言，输出另一种语言。翻译和"续写"不同——它不是"顺着写"，而是"先读完整句，再另起炉灶写"。所以早期 Transformer 是**编码器-解码器（encoder-decoder）**两段式：

```
输入 "今天天气好"  ──► 【编码器 Encoder】──► 整句的"语义摘要" ──► 【解码器 Decoder】──► 输出 "The weather is nice"
                       （看全文，双向）                              （逐个词生成，只能往左看）
```

| 部分 | 注意力怎么用 | 为什么 |
|---|---|---|
| 编码器 | **双向** self-attention：每个位置看全句所有位置 | 理解"整句"才翻得准 |
| 解码器 | **masked** self-attention（只往左看）+ **交叉注意力**（看编码器输出） | 生成时不能偷看未来；但必须参考"源句的意思" |

### 6.2 三个 attention 的三种用途（关键区别）

早期 Transformer 里"注意力"出现三次，各有分工：

```
1) 编码器的 self-attention：  源句内部，词与词互相关联
2) 解码器的 masked self-attention： 已生成部分内部，词与词互相关联（只能往左看）
3) 解码器的 cross-attention： 解码器的每个词 ← 去看编码器的所有词（跨语言桥）
```

**交叉注意力（cross-attention）**是早期 Transformer 独有的一环：Q 来自解码器，K/V 来自编码器。它负责"翻译时，当前生成到哪，源句的哪些词在影响我"。

### 6.3 关键配置（记住这张表，§7 会逐项对照）

| 组件 | 早期 Transformer（2017） | 说明 |
|---|---|---|
| 模型大小 | d_model=512，编码器 6 层 + 解码器 6 层 | 规模小，为翻译调参 |
| 头数 | 8 头，head_dim=64 | 512 / 8 |
| FFN | d_ff=2048（4 倍），激活用 ReLU | — |
| 位置编码 | **正弦/余弦**，**加**在 embedding 上 | 公式固定，不学习 |
| 归一化 | LayerNorm（post-norm：加完残差再归一） | 后来普遍改成 pre-norm |
| 注意力 | 缩放点积注意力，**除 $\sqrt{d_k}$** | 公式见 §3.3 |
| 训练技巧 | 教师强制（teacher forcing）、dropout、warmup | 教师强制见 6.4 |

**正弦位置编码**（一个例子，不用背）：给位置 $pos$ 的第 $2i$ 维配 $\sin(pos/10000^{2i/d})$、第 $2i+1$ 维配余弦——不同位置得到不同的向量，加进 embedding 后模型"看得见"位置。它是**固定公式、不参与训练**。

### 6.4 教师强制：训练时一次喂整句，不等它慢慢蹦

翻译训练如果按推理那样"一个词一个词生成再纠错"，太慢且易错。**教师强制（teacher forcing）**：训练时**直接把标准答案的右移一位**当解码器输入，一次并行算整句，loss 对比每个位置的预测和标准答案。推理时没有标准答案，才退回"自己蹦"。

> 一句话：**训练用标准答案喂（并行、快、稳），推理用自己生成的回填（自回归）。** 05 篇讲 KV cache 时你会再见到这个对比。

### 6.5 为什么后来 GPT 砍掉编码器、只留解码器

现在的主流 LLM（GPT、Llama、nanoChat）**都是 decoder-only**——没有编码器、没有交叉注意力。为什么？

1. **自回归任务只需要"往左看"**：续写/聊天是"顺着写"，不是"先读完再翻译"，编码器（读全文）派不上用场
2. **结构更简单**：少一套 cross-attention，训练和部署都省事
3. **事实证明够强**：把 decoder-only 堆大 + 海量数据 + RLHF，能力全面超过当年的 encoder-decoder

> 于是"Transformer 架构"从 2017 的"编码器+解码器全家桶"演变成了 2023 之后的"解码器专精"。**案例1 看历史，案例2 看今天。**

## 7. 案例2：nanoChat（Karpathy 的现代小型聊天模型）

### 7.1 定位

nanoChat（karpathy/nanochat）是一个**刻意做小、做简单的 decoder-only 聊天模型**：约 0.3B 参数（12 层 × 768 维），单卡 4090/A100 就能训练和推理。它是本仓库 05 篇的**部署案例主角**（05 篇 §5 讲怎么把它喂给 llama.cpp）。

它保留了 GPT 的一切骨架（§5.5 那套），但每一处细节都换成"更省、更稳、更现代"的选择。**用案例1 当参照系，nanoChat 的每个设计决定都看得懂。**

### 7.2 配置与结构

默认配置（真实源码 `gpt.py` 的 GPTConfig）：

```
sequence_len = 2048      # 上下文长度（最多看 2048 个词）
vocab_size   = 32768     # 词表大小
n_layer      = 12        # block 数
n_embd       = 768       # embedding 维度 d
n_head       = 6         # 查询头数（Q）
n_kv_head    = 6         # KV 头数（GQA 参数）
window_pattern = "SSSL"  # 滑动窗口：3 层短窗 + 1 层全窗，循环铺满
```

前向数据流（真实源码 `GPT.forward`）：

```python
x = self.transformer.wte(idx)     # ① 查表：token → [B, T, 768]
x = x.to(COMPUTE_DTYPE)
x = norm(x)                       # ② embedding 后先归一化
for i, block in enumerate(self.transformer.h):
    x = self.resid_lambdas[i] * x + self.x0_lambdas[i] * x0   # 残差标量
    x = block(x, ve, cos_sin, self.window_sizes[i], kv_cache) # ③ N 个 block
x = norm(x)                       # ④ 输出前再归一
logits = self.lm_head(x)          # ⑤ 投影回词表 → 下一个词的打分
```

### 7.3 逐项拆：nanoChat 和早期 Transformer 的 8 个差异

| # | 组件 | 早期 Transformer | nanoChat | 动机（"为什么这么改"） |
|---|---|---|---|---|
| ① | 位置编码 | 正弦加在 embedding 上 | **RoPE（旋转位置编码）** | 直接编码"相对位置"，外推到更长序列更稳 |
| ② | 归一化 | LayerNorm（post-norm） | **无参数 RMSNorm（pre-norm）** | 少一堆可学习参数 + 数值更稳 |
| ③ | FFN 激活 | ReLU / GELU | **ReLU²**（先 ReLU 再平方） | 更简单，且实验效果更好 |
| ④ | 线性层 | 带 bias | **无 bias** | 省参数，少训练波动 |
| ⑤ | 注意力 | 每头独立（MHA） | **GQA（分组查询注意力）** | 省 KV cache、省显存（见 7.4） |
| ⑥ | embedding/输出头 | 早期可共享权重 | **解耦（wte 和 lm_head 分开）** | 优化器各配学习率，训得更稳 |
| ⑦ | 注意力窗口 | 全部看全上下文 | **滑动窗口（"SSSL"）** | 长序列下省钱（见 7.4） |
| ⑧ | 其余工程细节 | — | QK-norm、embed 后归一、残差标量、smear/backout、logit softcap | 每个都是"稳定训练/推理"的小修补 |

逐项展开：

**① RoPE（旋转位置编码）**——把位置信息编码进 Q/K，而不是加进 embedding。做法是给 Q/K 的每对维度做一个随位置旋转的变换（`apply_rotary_emb`：`y1 = x1·cos + x2·sin`，见源码）。好处是**相对位置**直接表现为向量夹角——"第 3 个词和第 7 个词的关系"只取决于它们的相对距离，所以序列变长（外推）时更稳。

**② 无参数 RMSNorm**——`F.rms_norm(x, (x.size(-1),))`，连可学习缩放都省了。反正数值稳定主要靠"除均方根"，这一下省掉 N 层 × 768 个参数。

**③ ReLU² FFN**——`F.relu(x).square()`：先过 ReLU（负值清零），再整体平方。数学上等价 $x\cdot\mathrm{relu}(x)$，简单、无门控分支。

> ⚠️ **一个只有工程细节会撞上的坑**（05 篇 §5 会展开）：ReLU² 的激活值**最大可达 8.8 万**，超过 FP16 上限 65504——用 fp16 会静默溢出成 NaN（加载成功、输出全错）。所以 nanoChat 必须用 **bf16**（指数范围和 FP32 一样），这也是 02 篇提到的"BF16 需要 Ampere（sm_80+）"的原因。

**④ 无 bias**——所有 `Linear(bias=False)`。bias 在归一化（RMSNorm）存在时本来就冗余，去掉省参数、降过拟合。

**⑤ GQA（Grouped-Query Attention）**——多个查询头**共享**同一组 K/V 头：Q 有 6 头，K/V 只有 6 头（这里的 `n_kv_head = n_head`，即每个 Q 头一组，退化为 MHA；若 `n_kv_head < n_head` 就是真正的分组）。共享 KV 头意味着 **KV cache 变小**——直接对接 05 篇 §6.4"GQA 专门用来减小 KV cache"。

**⑥ 解耦 embedding 与输出头**——`wte`（词→向量）和 `lm_head`（向量→词）是**两份独立权重**（早期 Transformer 论文建议共享以省参，但 nanoChat 不共享），这样两者可以**配不同的学习率**（embedding 0.2 vs 输出头 0.004），训练更稳。

**⑦ 滑动窗口注意力**——不是每层都看全 2048 个词，而是按 `"SSSL"` 模式铺满 12 层：连续 3 层只看最近的 1/4 上下文（短窗 S），第 4 层看全窗（L），最后一层强制全窗。短窗层省计算、省 KV cache，全窗层保证"遥远的伏笔"仍能被看到。

**⑧ 工程小件**（各一句话）：

| 细节 | 作用 |
|---|---|
| QK-norm（q、k 归一化 + 乘 1.2） | 注意力分数更稳定（防 outlier） |
| embedding 后先归一 | 让第一层输入尺度统一 |
| 残差标量（resid/x0 lambdas） | 每层残差加一个可学习系数，早期层贡献更大 |
| smear（混入前一个词的 embedding） | 用极廉价的方式给每个位置补一点"上上文"信息 |
| backout（输出前减去中间层残差） | 去掉低层特征再投影，logits 更干净 |
| logit softcap（$15\,\tanh(x/15)$） | 把 logits 压到 ±15，防训练后期爆炸 |

### 7.4 三个和 05 篇直接挂钩的省钱点

把 7.3 的差异按"05 篇的加速视角"重排，nanoChat 每个设计都在为推理省钱：

| nanoChat 设计 | 省的是什么 | 05 篇对应 |
|---|---|---|
| **GQA**（⑤） | KV cache 变小 | §2 KV cache、§6.4 |
| **滑动窗口**（⑦） | 每步要读的 KV 变少 | §2.2 KV cache 显存 |
| **RoPE**（①） | 相对位置编码，长上下文更稳 | §1.4 长上下文很贵 |

> 你会发现：**"架构怎么设计"和"推理怎么加速"是同一件事的两面**——模型结构决定 KV cache 大小，KV cache 决定 decode 速度。这正是 05 篇的核心论点。

### 7.5 与仓库的关系：05 篇为什么拿它当"非标准架构"案例

nanoChat 不是 HF `transformers` 标准结构（它魔改了 FFN、加了 GQA 等），所以 05 篇 §5 用它演示了完整部署链路：

```
nanoChat checkpoint ──► convert_nanochat_to_gguf（自写转换脚本）
                      ──► llama.cpp fork（加了 nanochat 架构支持）
                      ──► bf16（ReLU² 溢出坑）
                      ──► GGUF 量化（可选）
```

**ReLU² → bf16 → 自写转换脚本**，这一串全都源于它的"非标准"架构——你在 7.3 学到的每一个差异，都在 05 篇变成了一个部署时要处理的坑。

## 8. 收尾：把 Transformer 挂回全仓库

### 8.1 你现在的完整视野

```
04 篇（PyTorch）：  你会搭 nn.Module 的 MLP、跑训练循环
                   ↕
本附件（架构）：    你会看懂 Transformer：词→数字 → 注意力 → block → 堆叠成 LLM
                   ↕
05 篇（加速）：     你会懂为什么它慢（内存墙）、怎么加速（KV cache / FlashAttention / 量化 / 引擎）
```

### 8.2 每个加速手段，现在都有落点了

| 05 篇的概念 | 对应的 Transformer 结构 | 为什么需要 |
|---|---|---|
| prefill / decode（§1.5） | 自回归生成（§1.3） | 一次一个词 → 前算过的想复用 |
| KV cache（§2） | 自回归时每个位置算一次 K/V（§3.2） | 算过的 K/V 存起来，别重算 |
| GQA（§6.4） | 多头里共享 KV 头（§7.3 ⑤） | 结构上就缩小 KV cache |
| FlashAttention（§3） | $\mathrm{softmax}(QK^\top/\sqrt{d_k})\,V$（§3.3） | 省 N×N 中间矩阵的带宽 |
| 量化（§4） | 权重 + KV cache 一起压 | decode 是 memory-bound |

### 8.3 一句话总结

> **Transformer = 用注意力让每个词直接"看到"其他词，再用 FFN 逐个消化、残差堆叠加深——LLM 的一切能力与一切性能瓶颈，都从这组组件而来。**

## 附：本文档出现过的关键公式

- 词向量：$X = \mathrm{wte}(idx)$，$X \in \mathbb{R}^{B\times T\times d}$（B=batch、T=序列长度、d=embedding 维度）
- 缩放点积注意力：$Attention(Q,K,V) = \mathrm{softmax}\!\left(QK^\top/\sqrt{d_k}\right)V$
- 多头：$MultiHead(Q,K,V) = \mathrm{Concat}(head_1,\ldots,head_h)W_o$，$head_i = Attention(QW_i^Q,\ KW_i^K,\ VW_i^V)$
- 因果 mask：$S_{i,j}\to-\infty$（当 $j > i$）
- FFN：$FFN(x) = W_2\,\sigma(W_1 x) + b$，nanoChat 的 $\sigma(z) = \mathrm{relu}(z)^2$
- 残差：$x \leftarrow x + \Delta(x)$
- 早期正弦位置编码：$PE(pos,\,2i) = \sin(pos/10000^{2i/d})$，奇数维用余弦
