## 0. 一句话答案

> **反向传播** = 训练中从 loss 往回、反着走的一整段，由**多个反向步骤**组成：每经过一个算子，用**链式法则**把上游梯度换成**它对每个输入的梯度**（单链乘局部导数、分叉汇合各路相加，见 §1.4/§3.4）——这就是"算梯度"。梯度全部算完后，才进入**另一件事：更新参数** $w\leftarrow w-\text{lr}\cdot\frac{\partial L}{\partial w}$，得到新 $w$。`loss.backward()` 是反向传播的一部分，但只负责"算梯度"：走完整张图、把 $\frac{\partial L}{\partial w}$ 填进各参数 `w.grad`（中间节点默认不留，见 §4.1）；**更新参数不是它干的**，那是 `optimizer.step()` 的事。

> ⚠️ **先钉死一个最容易搞混的点：`backward()` 只算梯度，不改参数。** 它把 $\frac{\partial L}{\partial w}$ 填进每个参数的 `w.grad`，但 `w` 自己的数值**一个都没动**。真正把 `w` 变小（更新）的是下一步：`optimizer.step()`（`step()` 内部干的就是 `w -= lr*w.grad`）。训练循环标准顺序：`zero_grad()`（清旧梯度）→ `forward()`（算出预测）→ `backward()`（只填 `w.grad`）→ `step()`（用梯度真改 `w`）。一句话记忆：**`backward()` 产的是"情报"（每个参数该往哪动、动多少），`step()` 才动手。**

用 3 行验证"它真没动 `w`"（可跑）：

```python
w = torch.tensor([1.0], requires_grad=True)   # 一个参数，初始值 1
L = (w * 3 - 2) ** 2                          # 随便造个损失
L.backward()
print(w)        # tensor([1.])  ← backward 之后还是 1，没变！
print(w.grad)   # tensor([6.])  ← 它只填了这里：梯度
w.data -= 0.1 * w.grad                        # 手动 step：这才真的改 w
print(w)        # tensor([0.4])
```

它不需要解方程、不需要近似、不需要重复跑前向。它只做一件事：**把"复合函数求导"这个数学过程，按计算实际发生的顺序，机械化地执行一遍。**

**在往下之前，先统一行话（默认你从没接触过机器学习，只懂 C/Java + 高数）**：

| 术语 | 记号 | 一句话含义 | C/Java 类比 |
|---|---|---|---|
| **样本** | — | 一条数据 = 一份输入 + 它该有的答案 | 测试用例（输入 + 期望输出） |
| **真值 / 目标** | $y$ | 样本里的"正确答案" | 测试用例里的期望输出 |
| **预测** | $\hat{y}$（读 "y-hat"） | 模型算出来的答案 | 被测函数的返回值 |
| **损失 loss** | $L$ | **预测和真值差多大**的一个数，越大越错，训练目标就是压小它 | 测试失败的"严重度" |
| **参数** | $w, b$ | 模型里**要调**的数（权重/偏置）；"模型" = 一堆参数 | 可调的配置项 |
| **学习率** | $lr$ | 每次更新参数走多大一步 | 步长 / 步进量 |
| **梯度下降** | — | 反复"沿负梯度挪一小步"，把 $L$ 压小 | 下山：每次都朝最陡的下坡迈一步 |
| **标量 / 向量** | — | 标量 = 一个数；向量 = 一串数 | `float` vs `float[]` |
| **隐藏层输出** | $\mathbf{h}$ | 一层"乘权重 + 加偏置"的结果，还没过激活函数 | 中间变量 |
| **激活值** | $\mathbf{a}$ | $\mathbf{h}$ 过激活函数（如 ReLU）之后的值 | 中间变量（过一道"开关"） |
| **单个样本损失** | $\ell$（小写 el） | 一个样本自己的损失；总损失 $L$ 往往是它外面套个平均 | 单条用例的失败分 |
| **batch 大小** | $N$ | 一次看多少个样本 | 一批测试用例数 |
| **第 $n$ 个样本** | $x_n,\ y_n$ | 一个 batch 里第 $n$ 个样本的输入、真值 | `batch[n]` |

两个容易混的记号（这篇统一这么用）：
- **$y$ = 真值（正确答案），$\hat{y}$ = 预测（模型输出）**。代码里预测变量常写成 `y_pred` 或 `y_hat`，都是 $\hat{y}$ 的意思。
- **$L$ 和 `loss` 是同一个东西**：$L$ 是数学记号，`loss` 是代码里的变量名。全文里 `loss.backward()` 的那个 `loss`，就是公式里这个 $L$——**没有第二个"损失"**，同一份"预测和真值差多大"的数，只是两个名字。
- **大写 $L$ 和小写 $\ell$ 不是一回事**：$\ell$ 是"单个样本"的损失，$L$ 是它在整个 batch 上平均/求和后的结果（§5 专讲）。

**为什么训练 = "把 $L$ 压小"**：参数一开始是随机数，预测必然很离谱（$L$ 很大）。训练反复调整参数，让预测越来越接近真值、$L$ 越来越小。整篇唯一要回答的问题是：**"该往哪个方向调、调多少"——答案就是梯度**。

剩下的篇幅，就是把这句话里每个词展开：梯度是什么（§1）、怎么手算（§2）、为什么反着走最省（§3）、计算机怎么自动做（§4）、在真实模型里长什么样（§5~§7）。

## 1. 数学热身：导数 → 偏导 → 梯度 → 链式法则

读者会 C/Java、有高数常识，所以这里只做"用代码的直觉重新点亮"的复习，不重新推导。

### 1.1 导数：一个变量时的"变化率"

`f(x)` 在 `x` 处的导数 `f'(x)`，就是"这里切线有多陡"，数值上等于自变量变一点点，函数值变多少倍的倍数：

$$f'(x) = \lim_{\varepsilon \to 0}\frac{f(x+\varepsilon) - f(x)}{\varepsilon}$$

C/Java 视角：就是"斜率"。$f(x) = x^2$ 在 $x=3$ 处 $f'(3)=6$，意思是"$x$ 增加一丁点，$f$ 增加大约 6 倍这么多"。

### 1.2 偏导：多变量，对其中一个求变化率

$f(x_1, x_2)$ 对 $x_1$ 的偏导 $\dfrac{\partial f}{\partial x_1}$，就是"把 $x_2$ 当常数，只动 $x_1$"。

### 1.3 梯度：所有偏导排成的向量

$$\nabla f = \left(\frac{\partial f}{\partial x_1},\ \frac{\partial f}{\partial x_2},\ \ldots,\ \frac{\partial f}{\partial x_n}\right)$$

**意义（训练的关键）**：梯度指向"$f$ 上升最快的方向"，那么**负梯度就是"$f$ 下降最快的方向"**。深度学习训练 = 一直沿负梯度挪参数，让 loss 越来越小：

$$w \leftarrow w - \text{学习率}\times\nabla_w\, L$$

（对一下记号：$w$ = 一个**参数**（权重），$\nabla_w L$ = "损失对 $w$ 的梯度"（回答"往哪个方向调、调多少"），$L$ 就是 §0 说的 **loss**——公式里写 $L$、代码里写 `loss`，同一个数。）

梯度就是优化器的燃料。而 `loss.backward()` 干的事，就是**把 $\nabla_w L$ 算出来**。

### 1.4 链式法则：整篇的发动机

**单变量版**：若 $y = f\big(g(x)\big)$，则

$$\frac{dy}{dx} = f'\big(g(x)\big)\cdot g'(x)$$

**多变量版**：若 $z$ 同时依赖 $x$ 和 $y$，而 $x, y$ 又依赖 $t$：

$$\frac{dz}{dt} = \frac{\partial z}{\partial x}\frac{dx}{dt} + \frac{\partial z}{\partial y}\frac{dy}{dt}$$

**人话总结（记住这两句就够）**：

```
串成一串 → 导数是乘起来的
分叉汇合 → 导数是加起来的
```

C/Java 直觉：把 `g` 的返回值喂给 `f`，两个函数"串"在一起。求导时，"变化信号"从 `f` 往回传，经过 `g` 时乘上 `g` 自己的斜率。**信号从后往前传**——这句话就是整篇的灵魂，也是"反向传播"名字的由来。

一个神经网络就是一条（其实是一张）巨大且分叉的复合函数，`loss` 是最外层的 $f$。链式法则给了一个机械步骤：从 loss 往回，每经过一个算子，就乘上它的局部导数。

## 2. 手算一次：从最简到小 MLP

### 2.1 热身：多项式拟合的手算梯度（最简，先感受"乘起来"）

经典入门问题：用多项式 $\hat{y} = a + bx + cx^2 + dx^3$ **拟合** $\sin$（拟合 = 找一条曲线尽量贴近已知数据点，这里是"用三次多项式去模仿 $\sin$ 的形状"）。先认符号：$x$ = **输入**（一个数，下面在 0~2π 里取 2000 个作为**样本**）；$a,b,c,d$ = 四个**参数**（要调的数）；$\hat{y}$ = **预测**（模型对输入 $x$ 输出的多项式值）。对第 $n$ 个样本：输入 $x_n$、真值 $y_n=\sin(x_n)$、预测 $y_{pred,n}$（代码写 `y_pred`）。**loss（损失 $L$）** = 所有点"预测 − 真值"的误差平方和：

$$L = \sum_n \big(y_{pred,n} - y_n\big)^2, \qquad y_{pred,n} = a + b\,x_n + c\,x_n^2 + d\,x_n^3$$

**手算梯度**（纯 numpy，不用 torch）——链式法则分两步：

$$\frac{\partial L}{\partial y_{pred}} = 2\,(y_{pred} - y) \qquad (\text{第 1 步：loss 对预测})$$

$$\frac{\partial L}{\partial a} = \sum_n \frac{\partial L}{\partial y_{pred,n}}\cdot 1,\quad \frac{\partial L}{\partial b} = \sum_n \frac{\partial L}{\partial y_{pred,n}}\cdot x_n,\quad \frac{\partial L}{\partial c} = \sum_n \frac{\partial L}{\partial y_{pred,n}}\cdot x_n^2,\quad \frac{\partial L}{\partial d} = \sum_n \frac{\partial L}{\partial y_{pred,n}}\cdot x_n^3 \qquad (\text{第 2 步：每个权重再乘上自己的"乘数"})$$

**记号细节（很多人卡在这）**：$\sum_n A_n\,B_n$ = 对每个 $n$ **先乘** $A_n\cdot B_n$，再把所有 $n$ 的结果**加起来**。累加号是"作用域"，管住它后面整个式子（没加括号就管到表达式结束）——所以是"先逐项乘、最后累加"，不存在"先加再乘"的读法。那为什么 `a` 那项"乘 $1$"看起来可加可不加？——**乘数是常数（不随 $n$ 变）时可以提出去**：$\sum_n A_n\cdot c = c\sum_n A_n$，$c=1$ 时就是恒等。但 $b,c,d$ 的乘数是 $x_n,\ x_n^2,\ x_n^3$（**随 $n$ 变**），提不出去，必须每个样本先乘再累加。下面代码里 `(grad_y_pred * x).sum()` 的括号就是在强制这个顺序。

对应代码就是 5 行（每个权重 `grad = (梯度_y_pred * 乘数).sum()`，那个 `.sum()` 就是 $\sum_n$）：

```python
grad_y_pred = 2.0 * (y_pred - y)              # ① loss 对预测的梯度
grad_a = grad_y_pred.sum()                    # ② 权重 a 的乘数是 1
grad_b = (grad_y_pred * x).sum()              #    b 的乘数是 x
grad_c = (grad_y_pred * x ** 2).sum()         #    c 的乘数是 x²
grad_d = (grad_y_pred * x ** 3).sum()         #    d 的乘数是 x³
```

**注意**：这四个梯度都是"整个样本集求和"出来的——这就是 §5 要说的 batch 梯度；而"每个权重乘的是各自在 $y_{pred}$ 里的系数"——这就是链式法则的"一段段乘起来"。**最简手算到这里就结束了**。

### 2.2 正规军：一个两层 MLP 的完整梯度

上面只有一个输出 $\hat{y}$（§2.1 那个多项式）；现在把模型换成真正的**两层网络**（2 输入 → 隐藏 2 神经元 + ReLU → 输出 1，损失用 **MSE**——均方误差，就是 §2.1 那个"误差平方和"）。（两个新词：**ReLU** = `max(x,0)`，负数归零、正数原样放行；**激活** = 给每层输出加一道非线性"开关"，否则多层线性叠加还是线性的，堆再多层也等于一层。）

```python
x  = [1, 0]              # 输入
W1 = [[1, 2],            # 隐藏层权重（参数）
      [3, 4]]
b1 = [0.5, -0.5]         # 隐藏层偏置（参数）
W2 = [0.1, 0.2]          # 输出层权重（参数，1×2）
b2 = [0]                 # 输出偏置（参数）
y  = 1                   # 真值（正确答案）

h     = W1 @ x + b1      # 隐藏层线性
a     = relu(h)          # 激活
y_hat = W2 @ a + b2      # 预测（模型输出）
L     = (y_hat - y) ** 2 # 损失：预测和真值差多大
```

**对照 §0 行话表认一遍这里的记号**：`x` = 输入，`W1`/`b1`/`W2`/`b2` = 参数（权重/偏置），`y` = 真值，`h` = 隐藏层线性输出，`a` = 激活之后，`y_hat`（= $\hat{y}$）= 预测，`L`（= loss）= 损失。下面的表格里，粗体 $\mathbf{x},\mathbf{h},\mathbf{a}$ = **向量**（一串数）、大写 $W$ = **矩阵**，与代码完全对应。

**这一节的所有数字我都用 PyTorch 验证过**（见 §2.5 复现代码），边看边对。

#### 前向：按顺序算出每个中间值（全存下来）

| 步骤 | 计算 | 结果 |
|---|---|---|
| ① | $\mathbf{h} = W_1\mathbf{x} + \mathbf{b}_1$ | $\mathbf{h} = [1.5,\ 2.5]$ |
| ② | $\mathbf{a} = \mathrm{relu}(\mathbf{h})$ | $\mathbf{a} = [1.5,\ 2.5]$ |
| ③ | $\hat{y} = W_2\,\mathbf{a} + b_2$ | $\hat{y} = 0.65$ |
| ④ | $L = (\hat{y}-y)^2$ | $L = 0.1225$ |

注意：**每个中间值都要存着**，反向时要用。

#### 反向：从 loss 开始，一路往回乘

原理：我们已经知道 $L$ 对 $y$ 的导数（第一步现算），那么对"再往前一步"的中间量，就用链式法则——**乘上这一步的局部导数**。关键口诀：**已经有的上游梯度 × 本地的偏导**。

| 步骤 | 局部规则 | 计算 | 得到 |
|---|---|---|---|
| ⑤ | $L=(\hat{y}-y)^2 \ \Rightarrow\ \dfrac{\partial L}{\partial \hat{y}}=2(\hat{y}-y)$ | $2(0.65-1)$ | $\dfrac{\partial L}{\partial \hat{y}} = -0.7$ |
| ⑥ | $\hat{y} = W_2\mathbf{a}\ \Rightarrow\ \dfrac{\partial L}{\partial W_2[j]} = \dfrac{\partial L}{\partial \hat{y}}\,a_j$ | $-0.7 \times [1.5, 2.5]$ | $\dfrac{\partial L}{\partial W_2} = [-1.05,\ -1.75]$ |
| ⑦ | $\hat{y} = W_2\mathbf{a}\ \Rightarrow\ \dfrac{\partial L}{\partial a_j} = \dfrac{\partial L}{\partial \hat{y}}\,W_2[j]$ | $-0.7 \times [0.1, 0.2]$ | $\dfrac{\partial L}{\partial \mathbf{a}} = [-0.07,\ -0.14]$ |
| ⑧ | $\mathrm{relu}$ 门：$a_j = \max(h_j,0)$，$h_j>0$ 放行、否则归零 | $\mathbf{h}$ 两个都 $>0$ | $\dfrac{\partial L}{\partial \mathbf{h}} = [-0.07,\ -0.14]$ |
| ⑨ | $h_i = \sum_j W_1[i][j]\,x_j + b_{1,i}\ \Rightarrow\ \dfrac{\partial L}{\partial W_1[i][j]} = \dfrac{\partial L}{\partial h_i}\,x_j$ | 见下面展开 | $\dfrac{\partial L}{\partial W_1} = \begin{bmatrix} -0.07 & 0\\ -0.14 & 0 \end{bmatrix}$ |
| ⑩ | $\dfrac{\partial L}{\partial \mathbf{b}_1} = \dfrac{\partial L}{\partial \mathbf{h}}$ | | $\dfrac{\partial L}{\partial \mathbf{b}_1} = [-0.07,\ -0.14]$ |

⑨ 的展开（读者最能看出"梯度形状跟权重一样"的地方）：

$$\frac{\partial L}{\partial W_1[0][0]} = \frac{\partial L}{\partial h_1}\,x_1 = (-0.07)(1) = -0.07, \qquad \frac{\partial L}{\partial W_1[0][1]} = \frac{\partial L}{\partial h_1}\,x_2 = (-0.07)(0) = 0$$

$$\frac{\partial L}{\partial W_1[1][0]} = \frac{\partial L}{\partial h_2}\,x_1 = (-0.14)(1) = -0.14, \qquad \frac{\partial L}{\partial W_1[1][1]} = \frac{\partial L}{\partial h_2}\,x_2 = (-0.14)(0) = 0$$

### 2.3 同一个拟合，三种写法——"自动"到底免掉了什么

§2.1 的多项式拟合，业界有标准的三级递进（PyTorch 官方教程就是这么教的），正好把"手算 → 自动"的差别放大到最大：

| 版本 | 用啥 | **梯度**（$\partial L/\partial w$）谁算 | **参数更新**（$w\leftarrow w-\text{lr}\cdot\text{grad}$）谁做 |
|---|---|---|---|
| ① 手算（numpy） | `numpy` | 你：`grad_a = grad_y_pred.sum()` … | 你：`a -= lr*grad_a` |
| ② 手算（torch） | `torch.Tensor` | 你（换成 tensor 语法） | 你 |
| ③ 自动（autograd） | `nn.Sequential` + `backward()` | **`loss.backward()` 自动算好，填进 `p.grad`** | 你：`for p in model.parameters(): p -= lr * p.grad`（或用 `optimizer.step()`） |

**盯住上表的两列分工**：`backward()` 只负责"梯度"那一列——把 $\partial L/\partial w$ 填进每个 `p.grad`，**不碰参数**。"更新参数"是另一列、另一件事，**反向传播不包括它**。一次训练迭代其实是四件事：前向（算 loss）→ `backward()`（算梯度）→ 更新参数 → `zero_grad()`（清旧梯度）。

对比的关键在 ③：`loss.backward()` 一行，代替了 ①② 里你手写的那 4 行梯度公式。**模型越复杂，这 4 行会指数级变多**——MLP 还凑合，CNN/Transformer 手写反向就是噩梦（§6、§7）。autograd 的存在意义，就是把这部分永远免掉。

```python
# 版本③（用 nn.Sequential）—— 手写梯度的 4 行没了，只剩这 4 行
model = nn.Sequential(nn.Linear(3, 1), nn.Flatten(0, 1))
loss_fn = nn.MSELoss(reduction='sum')
loss = loss_fn(model(xx), y)
model.zero_grad(); loss.backward()          # ← 自动微分在这一行发生
for p in model.parameters(): p -= lr * p.grad
```

### 2.4 从这一遍，提炼出"反向"的规律

1. **每步只做"乘法"**：上游梯度 × 局部偏导。不需要任何解方程。
2. **中间值被复用了**：$\frac{\partial L}{\partial \mathbf{a}}$（⑦）算了之后，⑧⑨⑩全在它的基础上继续。
3. **每个中间值的梯度只算一次**，从 loss 往回一趟，所有参数梯度齐了。这正是下一节"为什么反着走最省"。
4. **梯度的形状和参数完全一样**：$\frac{\partial L}{\partial W_1}$ 是 $2\times2$、$\frac{\partial L}{\partial \mathbf{b}_1}$ 是 $(2,)$、$\frac{\partial L}{\partial W_2}$ 是 $(1,2)$。这是 PyTorch 里 `w.grad` 能直接和 `w` 相减的前提。

### 2.5 对照 PyTorch（可复现）

```python
import torch
x  = torch.tensor([1.0, 0.0])
W1 = torch.tensor([[1.,2.],[3.,4.]], requires_grad=True)
b1 = torch.tensor([0.5,-0.5], requires_grad=True)
W2 = torch.tensor([[0.1,0.2]], requires_grad=True)
b2 = torch.tensor([0.0], requires_grad=True)

h = W1 @ x + b1
a = torch.relu(h)
y_pred = W2 @ a + b2
y_true = torch.tensor([1.0])          # 真值
L = (y_pred - y_true).pow(2).sum()
L.backward()

print(W2.grad)   # tensor([[-1.0500, -1.7500]])
print(W1.grad)   # tensor([[-0.0700,  0.0000], [-0.1400,  0.0000]])
print(b1.grad)   # tensor([-0.0700, -0.1400])
```

和手算完全一致。

## 3. 为什么"反向"是对的、又是快的：计算图

### 3.1 把计算画成一张图（DAG）

§2.2 的 MLP 前向，可以画成一张**有向无环图（DAG）**：

```
x ──┐
W1 ─┼─→ h ─→ a(=relu) ─→ ŷ ─→ L
b1 ─┘                          ↑
W2 ─→ ────────────────────────┘   (ŷ = W2·a + b2)
b2 ─→ ────────────────────────┘   (L = (ŷ−y)²)
```

- **节点** = 一个中间量（数值）
- **边** = 依赖关系（`h` 依赖 `W1, x, b1`）
- 图是**有向无环**的：数据只从输入往 loss 流，不会绕圈。

**C/Java 直觉**：这张图就像一个**表达式树/AST**。你写 `h = W1@x + b1` 时，编译器脑子里就有这么一棵树。PyTorch 在 `forward` 时也会把这棵树**实际建出来**（每个算子的输出节点记下"我是谁算出来的"）——这就是 `tensor.grad_fn` 干的事。

### 3.2 前向录图，反向走图

**前向**：从输入到 loss，按拓扑序（依赖在前、被依赖在后）把每个节点的值算出来并缓存。

**反向**：从 loss 往回，**逆拓扑序**走一遍。走到每个节点时：

$$\text{节点 } z \text{ 的梯度} = \text{上游梯度} \times \frac{\partial z}{\partial(\text{输入})}$$

（`上游梯度` = 已经算好、缓存着的那份；`∂z/∂(输入)` = 本算子的局部导数。）正因为反向时"上游梯度"恰好已算好，每个节点只需 $O(1)$ 本地计算——**整张图反走一趟就完事**。

**为什么这是最优的**：一个参数 $w$ 的梯度需要"从 loss 一路乘到 $w$"。如果正向一个个参数地追（对每个参数重新跑一遍链式），那就是"参数个数 × 图大小"的工作量。反着走，**每个节点的梯度只算一次**，总量是 $O(\text{图大小}) \approx 2\sim3$ 倍前向的计算量，**和参数个数无关**。1000 个参数和 10 亿个参数，都只要这一趟反向。

### 3.3 三种求梯度方式的对比（C/Java 视角）

| 方式 | 做法 | 拿全部参数梯度要花多少 | 精度 |
|---|---|---|---|
| **数值微分** | 每个参数扰动 $\varepsilon$，用 $\dfrac{f(w+\varepsilon)-f(w)}{\varepsilon}$ 近似 | 参数个数 + 1 次前向 | 有截断 + 舍入误差 |
| **符号微分** | 把 loss 的表达式用求导法则整个展开、重写 | 表达式爆炸（中间式指数增长） | 精确，但展开不了 |
| **自动微分（反向）** | 前向录图，反向沿图走一遍 | **1 次前向 + 1 次反向** | 精确（除浮点本身） |

三个类比，C/Java 程序员秒懂：

- **数值微分 ≈ 调试器里反复采样**：想求 $f$ 在一点的斜率，就实际跑 $f(x+\varepsilon)$ 和 $f(x)$，量差值。对每个参数都这么干一次——**跑一万次前向**。10 亿参数的模型，这辈子跑不完。
- **符号微分 ≈ 把整个表达式硬展开重写**：$(a+b+c)^{400}$ 你手写展开会疯；符号微分就是把整个神经网络的表达式按求导法则展开成一张巨大无比的公式——中间式子成指数增长，内存先爆。
- **自动微分 ≈ 不动源码，录"实际执行路径"**：你的模型代码一个字不改，前向时把**这次真正跑了哪些算子**记下来（一张图），然后在这张图上反走一趟。**它不重写表达式，它导的是"这次计算实际走过的数值路径"。** 这正是它的优雅之处。

### 3.4 一个变量被用两次 → 梯度要相加（`zero_grad` 的由来）

看链式法则的多变量版（§1.4）：如果 $z$ 同时依赖 $x$ 和 $y$，而两者都依赖 $t$，那么 $\dfrac{dz}{dt} = \dfrac{\partial z}{\partial x}\dfrac{dx}{dt} + \dfrac{\partial z}{\partial y}\dfrac{dy}{dt}$。

**翻译成图的话**：一个节点如果被两个下游算子使用（分叉后汇合），它的梯度 = **各路梯度之和**。

```python
z  = x * y            # x 被用了
z2 = x * x            # x 又被用了
L  = z + z2           # 分叉汇合
# dL/dx = dL/dz·y + dL/dz2·(2x)   ← 两路加起来
```

PyTorch 正是这么做的：`backward` 时对叶子节点的 `.grad` 是**累加**（`+=`）。这是故意设计——方便你把损失拆成几份分别 backward 再求和。

**这就是为什么训练循环里每步要 `optimizer.zero_grad()`**：如果不清，上一步的梯度还留在 `.grad` 里，这一次 `backward` 会叠上去，梯度越滚越大（§4.5 再展开）。

## 4. autograd 的实现思路：把"手算"自动化

现在你已经会手算了。autograd 就是把 §2 的这套流程，用程序机械地执行。核心就三点。

### 4.1 每个"值"存三样东西

```
一个 Tensor 的简化概念（C 视角）：

struct Tensor {
    float* data;           // 前向算出来的数值
    float* grad;           // 反向时填的梯度（对参数节点保留）
    BackwardFn* grad_fn;   // "我是哪个算子算出来的" → 指向一个反向函数
};
```

`grad_fn` 是这个数据结构的灵魂：**它让每个节点都知道自己是谁的孩子、父母是谁**——图就是靠它串起来的。

> **理解 `grad_fn` 的一个好框架**（来自当年学 autograd 的笔记）：求梯度拆两步——**① 对变量求"微分表达式" $f'(\cdot)$，② 把实际值代进去得梯度 $f'(x)$**。`grad_fn` 就是第①步的结果（挂在每个节点上的"微分表达式"），backward 走图时执行第②步（代入）。叶子节点（输入、参数）没有表达式，所以 `w.grad_fn` 是 `None`，而 `z.grad_fn`、`loss.grad_fn` 都是非空——打印出来能直接看到是哪个算子（`AddBackward`、`MulBackward`…）。

### 4.2 前向时建图，反向时逆序走

**每个算子天生带两个函数**：`forward`（算结果）和 `backward`（按本地规则回传梯度）。前向每执行一个算子，就把"输出节点 + 它的 backward"记下来；反向时从 loss 出发，逆着走：

```python
# 概念伪代码（和 PyTorch 的机制一一对应）
L = z.add(b)          # 前向：L.data = z+b；L.grad_fn = AddBackward
z = w.mul(x)          # 前向：z.data = w*x；z.grad_fn = MulBackward

# 反向：从 L 开始，每个 grad_fn 调用它自己的 backward
dL = 1.0                                        # 种子：dL/dL = 1
(dz, db) = L.grad_fn.backward(dL)               # add 规则：梯度透传 → dz = 1, db = 1
(dw, dx) = z.grad_fn.backward(dz)               # mul 规则：互换 → dw = dz*x, dx = dz*w
```

每个 `backward` 的输入是**上游梯度**，输出是**对每个输入的本地梯度**。所谓"自动微分"，就是把这些 `backward` 按逆拓扑序自动串起来——**你负责写 forward，库替你写 backward**。

### 4.3 本地求导规则速查表（背下来就能看懂任何模型的反向）

设节点 $z = f(x, y)$，已知上游梯度 $\frac{\partial L}{\partial z}$：

| 算子 | 前向 | 反向：对 $x$ 的梯度 | 反向：对 $y$ 的梯度 | 一句话 |
|---|---|---|---|---|
| 加法 | $z = x+y$ | $\dfrac{\partial L}{\partial z}$ | $\dfrac{\partial L}{\partial z}$ | 上游梯度**原样透传** |
| 减法 | $z = x-y$ | $\dfrac{\partial L}{\partial z}$ | $-\dfrac{\partial L}{\partial z}$ | $+1/-1$ 传 |
| 乘法 | $z = xy$ | $y\,\dfrac{\partial L}{\partial z}$ | $x\,\dfrac{\partial L}{\partial z}$ | 梯度**互换**着乘 |
| 除法 | $z = x/y$ | $\dfrac{1}{y}\dfrac{\partial L}{\partial z}$ | $-\dfrac{x}{y^2}\dfrac{\partial L}{\partial z}$ | 按公式乘 |
| ReLU | $z=\max(x,0)$ | $\dfrac{\partial L}{\partial z}\cdot\mathbf{1}[x>0]$ | — | **0/1 门** |
| 矩阵乘 | $z = XW$ | $\dfrac{\partial L}{\partial z}W^\top$ | $X^\top\dfrac{\partial L}{\partial z}$ | **转置乘回去** |
| Softmax | $p=\mathrm{softmax}(s)$ | $p\odot\left(\dfrac{\partial L}{\partial p} - \sum_j p_j\dfrac{\partial L}{\partial p_j}\right)$ | — | **先"去均值"再逐元素乘 $p$** |
| 卷积 | $z=\mathrm{conv}(x,w)$ | **转置卷积**（§6.3） | **窗口累加**（§6.2） | §6 专讲 |
| 池化 max | $z=\max(\text{窗口})$ | 只回传给最大元素 | — | **最大者得** |
| 池化 avg | $z=\text{avg}(\text{窗口})$ | 每个元素 $\tfrac{1}{k}$ | — | **均分** |

**看出来了吗**：几乎全部是"加法/乘法/门/转置"。真正"手算会疯"的只有 Softmax 和注意力（§7），但它们的规则也是上面这张表一层层拼出来的。

### 4.4 和编译器的类比（对 C/Java 读者最顺）

| 概念 | 编译 / 解释 | autograd |
|---|---|---|
| 表达式树 | AST / IR | 计算图（DAG） |
| 求值 | 解释器跑一遍 | 前向算数值 |
| 遍历方式 | 后序遍历 | 反向 = 逆拓扑序遍历 |
| 每节点动作 | 执行运算 | 乘上游梯度 × 本地偏导 |
| 动态性 | 运行时才知道形状 | 前向**动态建图**（跑几次算几次） |

特别提"动态建图"：PyTorch 是**每次 forward 都现场建一张新图**，所以 `if`、`for`、Python 动态分支都支持（图随实际执行路径变化）。这也是为什么它叫"define-by-run"——和图灵机一样灵活，代价是建图有点开销（§4.5 的 `no_grad` 就是省这笔）。

### 4.5 四个"为什么"（PyTorch 里天天见）

**① 为什么 `backward()` 要求 loss 是标量？**

反向需要一个"种子"：从 $\frac{\partial L}{\partial L} = 1$ 开始。如果 $L$ 是**标量**，种子唯一，不用问。如果 $L$ 是**向量/矩阵**，就得告诉它"每个元素的梯度是多少"（`backward(gradient=...)` 参数），否则不知道拿什么权重合并各分量——数学上就是"链式法则需要一个明确的起点梯度"。

**② 为什么必须 `zero_grad()`？**

`.grad` 是**累加**的（设计如此，方便多份损失求和）。不清零，这一轮 `backward` 会叠到上一轮的梯度上——`w.grad` 滚成两倍、三倍，参数更新就乱套。所以训练循环的标准姿势是：`zero_grad()` → `forward` → `backward` → `step`。

**③ 为什么原地操作（`add_`）会报错破坏图？**

反向时每个算子要按本地规则算，需要**它 forward 时看到的原始输入值**（比如 ReLU 需要知道 $h$ 的正负号）。原地操作（`add_`、`relu_`）会把节点的值**覆盖掉**，backward 时取不到原始值，就报错。所以训练中"该建图的变量"用 `add`，别用 `add_`。

**④ 为什么 `backward()` 不能连续调两次？**

图是**用完即毁**的：一次 `backward()` 后，中间缓存（`saved tensors`）就被释放了，再调一次会报 `RuntimeError: Trying to backward through the graph a second time`。需要二次反向时加 `retain_graph=True` 保住图——比如 GAN 里要先后对两个 loss 反向。**默认"用完即毁"是为了省内存**：图的中间值占显存，不该一直留着。

**⑤ `torch.no_grad()` 干什么用？**

**不建图**。推理阶段只需要数值、不需要梯度，`with torch.no_grad():` 让 forward 不再记录 grad_fn——省内存、省建图开销，快不少。（`tensor.detach()` 是剪断某条边，效果类似。）

## 5. 案例一：MLP——从单样本到 batch 平均梯度

§2.2 手算的是**一个样本**。真实训练是 **一个 batch 多个样本**，loss 取平均：

$$L = \frac{1}{N}\sum_{n=1}^{N}\ell(x_n, y_n)$$

（符号：$N$ = 一个 batch 里样本数；$x_n$、$y_n$ = 第 $n$ 个样本的**输入**和**真值**；小写 $\ell$（读 "el"）= **单个样本**的损失，外面套 $\frac{1}{N}\sum_{n=1}^N$ 取**平均**后才是总损失 $L$——所以 $\ell$ 和 $L$ 不是同一个东西。对照代码：`loss = loss_fn(pred, y).mean()`，`loss_fn(pred,y)` 逐个样本算 $\ell$，`.mean()` 就是那个平均。）

反向时，因为"求和"的本地规则是透传（§4.3），**batch 的梯度 = 每个样本梯度的平均**：

$$\frac{\partial L}{\partial w} = \frac{1}{N}\sum_{n=1}^{N}\frac{\partial \ell(x_n)}{\partial w}$$

两个实际后果（读训练代码时有用）：

1. **batch 大小影响梯度幅度**：batch 越大，平均越平滑（方差小），训练更稳；batch=1 就是随机梯度下降，噪声最大。
2. **学习率要跟着 batch 走**：因为梯度是平均，所以增大 batch **不会**让梯度整体变大——这也是为什么"加大 batch 通常不用改学习率"。

> MLP 反向的全部"新东西"在 §2 已经讲完：线性层转置乘、ReLU 门、分叉求和。CNN/Transformer 只是**把"算子"换成更复杂的几个**，机制完全一样。

## 6. 案例二：CNN——梯度怎么穿过卷积、池化

CNN 里反向的难点只有一个：**梯度怎么穿过 `Conv2d` 和 `Pool`**。ReLU 的规则和 MLP 完全一样（0/1 门），不再重复。

### 6.1 卷积前向：滑动窗口点积

输出每个位置 = 核与输入对应窗口的逐元素乘积之和：

$$out[i,j] = \sum_{k_h, k_w} x[i+k_h,\ j+k_w]\cdot w[k_h, k_w] \ (+ \ b)$$

（符号：$x$ = 输入图像，$w$ = **卷积核**（权重，参数），$out$ = 卷积输出，$b$ = 偏置；$i,j$ = 输出里的行/列坐标，$k_h,k_w$ = 核里的行/列坐标。核滑到输出位置 $(i,j)$ 时，盖住的输入是 $x[i{+}k_h,\ j{+}k_w]$，把这一窗口和核**逐元素相乘再求和**就得到 $out[i,j]$。）

下面用最小可手算的例子（核 $2\times2$、输入 $3\times3$、输出 $2\times2$，核取 $w=\begin{bmatrix}1 & 2\\ 3 & 4\end{bmatrix}$ 方便读者）：

```
输入 x                核 w           输出 out
1 2 3                 1 2            37  47
4 5 6                 3 4            67  77
7 8 9
```

（例如 $out[0,0] = 1\cdot1+2\cdot2+4\cdot3+5\cdot4 = 37$。）

### 6.2 权重的梯度：每个窗口"输入"累加

$\dfrac{\partial L}{\partial w[k_h,k_w]}$ = 把所有输出位置的上游梯度 × 对应窗口里的输入，**加起来**：

$$\frac{\partial L}{\partial w[k_h,k_w]} = \sum_{i,j}\ \frac{\partial L}{\partial out[i,j]}\cdot x[i+k_h,\ j+k_w]$$

例子里 $\frac{\partial L}{\partial out}$ 全取 1（即 `out.sum().backward()`），于是：

$$\frac{\partial L}{\partial w} = \begin{bmatrix} 1{+}2{+}4{+}5 & 2{+}3{+}5{+}6\\ 4{+}5{+}7{+}8 & 5{+}6{+}8{+}9 \end{bmatrix} = \begin{bmatrix} 12 & 16\\ 24 & 28 \end{bmatrix}$$

**直觉**：每个核元素，被"所有盖住过它的窗口"共同更新。

### 6.3 输入的梯度：转置卷积（"反卷积"的正名）

$\dfrac{\partial L}{\partial x[i,j]}$ = 把所有"用到了 $x[i,j]$ 的窗口位置"的梯度 × 核元素，加起来：

$$\frac{\partial L}{\partial x[i,j]} = \sum_{k_h, k_w}\ \frac{\partial L}{\partial out[i-k_h,\ j-k_w]}\cdot w[k_h, k_w]$$

等价于：**把核旋转 180°、反向滑一遍**——这就是"转置卷积"（transposed convolution），**不是**解卷积（deconvolution，那个是"从输出恢复输入"，通常不存在）。autograd 里它只是一个"核对梯度回传"的规则。例子里：

$$\frac{\partial L}{\partial x} = \begin{bmatrix} 1 & 3 & 2\\ 4 & 10 & 6\\ 3 & 7 & 4 \end{bmatrix}$$

读者可以验证一个数：$\frac{\partial L}{\partial x[1,1]}$ 用了四个窗口，$= 1+2+3+4 = 10$。✓

### 6.4 池化反向：最大值者得 / 平均均分

- **MaxPool**：前向只记住每窗口里的**最大值在哪个位置**；反向把整份梯度**只回给那个位置**，其他位置 0：

$$x=\begin{bmatrix}1 & 2\\ 3 & 4\end{bmatrix}\ \to\ \text{pool}(2)\ \to\ 4\,(\text{最大})\qquad \frac{\partial L}{\partial x} = \begin{bmatrix}0 & 0\\ 0 & 1\end{bmatrix}\ \leftarrow\ \text{只有 }4\text{ 拿到}$$

- **AvgPool**：每窗口取平均，反向把梯度**均分**给窗口内每个元素：

$$\frac{\partial L}{\partial x} = \begin{bmatrix} 0.25 & 0.25\\ 0.25 & 0.25 \end{bmatrix}$$

### 6.5 数值验证（PyTorch 对照，可复现）

```python
import torch
conv = torch.nn.Conv2d(1, 1, 2)                 # 核默认随机，先写死
with torch.no_grad():
    conv.weight.copy_(torch.tensor([[[[1.,2.],[3.,4.]]]])); conv.bias.zero_()
x = torch.arange(1.0, 10.0).reshape(1,1,3,3); x.requires_grad_(True)
out = conv(x)
out.sum().backward()                            # 让 dL/dout 全为 1
print(conv.weight.grad[0,0])    # [[12,16],[24,28]]
print(x.grad[0,0])              # [[1,3,2],[4,10,6],[3,7,4]]
```

### 6.6 CNN 的梯度流向（为什么"深"会导致梯度问题）

梯度从 loss 出发，要一路穿过**所有卷积层**（每层转置卷积一次）才能到第一层。每穿一层都要乘核的数值。**如果核的"大小" $\lVert w\rVert < 1$（$\lVert w\rVert=\sqrt{\sum w^2}$，各元素平方和的平方根），梯度一路衰减** → 浅层几乎学不动（**梯度消失**）；**$\lVert w\rVert > 1$ 则一路放大** → 发散（**梯度爆炸**）。这就是为什么深度网络需要残差连接（Transformer 里也是它）、归一化、好的初始化——本质上都在调控"反向这一路乘法"的总量。**autograd 算得再准，也救不了一个数值上注定消失/爆炸的梯度**——这是理解"为什么要有那些训练技巧"的地基。

## 7. 案例三：Transformer——注意力，"手算会疯"的地方

注意力是整条反向链里**唯一公式复杂**的环节。本节把它拆开：公式先列出来、再给数值、再解释"为什么手算会疯但 autograd 不会"。

### 7.1 注意力前向四步（单头）

先认符号（一个长度为 $n$ 的句子，每个位置 $d$ 维）：

| 记号 | 含义 |
|---|---|
| $X$ | 输入矩阵：$n$ 行（$n$ 个位置）× $d$ 列（每个位置 $d$ 个数） |
| $W_q,W_k,W_v$ | 三个线性层的权重（参数），把 $X$ 投影成 $Q,K,V$ |
| $Q,K,V$ | **查询 / 键 / 值**：每个位置拿自己的 $Q$ 去和所有 $K$ 比相似度，再按相似度加权混合所有 $V$ |
| $d$ | 单个头的维度（这里 $Q,K,V$ 每行几个数） |
| $S$ | 注意力得分矩阵（$n\times n$：位置 $i$ 和位置 $j$ 有多像） |
| $P$ | 得分 $S$ 做 softmax 后的权重（每行和为 1） |
| $O$ | 注意力输出（按 $P$ 加权混合 $V$ 得到） |

四步：

$$S = \frac{QK^\top}{\sqrt{d}} \qquad (1)\ \text{打分：query 和每个 key 有多像}$$

$$P = \mathrm{softmax}(S, \ \text{dim}=-1) \qquad (2)\ \text{归一化成权重（每行和为 }1)$$

$$O = P\,V \qquad (3)\ \text{加权求和：按权重混合 value}$$

$$L = \text{loss}(O, \cdots) \qquad (4)\ \text{下游损失}$$

（Q、K、V 分别来自 $XW_q$、$XW_k$、$XW_v$，是线性层——它们自身是 §5 的 matmul 规则，不重复。）

### 7.2 Softmax 反向：唯一"公式复杂"的地方

Softmax 的输出**和为 1**，所以它反向时天然带一个"减去平均值"的项（保证梯度在某方向上和为 0）：

（符号：小写 $s$ = §7.1 里 $S$ 的**某一行**（一个位置对所有位置的得分），$p$ = 这一行 softmax 之后的结果（$P$ 的对应行）；$\frac{\partial L}{\partial p}$ = 上游传下来的梯度（下面数值例里简写为 $\mathbf{g}$）；$j$ 遍历这一行的每个位置；$\odot$ = 逐元素相乘。）

$$p = \mathrm{softmax}(s) \qquad\Longrightarrow\qquad \frac{\partial L}{\partial s} = p \odot \left(\frac{\partial L}{\partial p} - \sum_j p_j\frac{\partial L}{\partial p_j}\right), \qquad \odot\ \text{为逐元素乘}$$

**数值例**（已用 PyTorch 验证）：

$$\mathbf{s} = [1.0,\ 2.0,\ 0.5],\quad \mathbf{p} = [0.2312,\ 0.6285,\ 0.1402],\quad \mathbf{g} = \frac{\partial L}{\partial \mathbf{p}} = [1.0,\ 0.5,\ 0.0]$$

$$\sum_j p_j g_j = 0.2312(1) + 0.6285(0.5) + 0.1402(0) = 0.5455$$

$$\mathbf{g}-\textstyle\sum = [0.4545,\ -0.0455,\ -0.5455] \qquad\Rightarrow\qquad \frac{\partial L}{\partial \mathbf{s}} = \mathbf{p}\odot(\mathbf{g}-\textstyle\sum) = [0.1051,\ -0.0286,\ -0.0765] \quad \checkmark$$

**手算会疯的第一个点来了**：$\frac{\partial L}{\partial s_i}$ 依赖**所有** $p_j$（那个求和项）——softmax 把同一行的位置全"耦合"在一起。一行 512 个位置，每个梯度都要遍历一遍全行。

### 7.3 Q / K / V 的梯度（已验证与 PyTorch 一致）

$$\frac{\partial L}{\partial V} = P^\top\frac{\partial L}{\partial O} \qquad \text{每个 } V \text{ 收集"所有用它的位置"的加权梯度}$$

$$\frac{\partial L}{\partial P} = \frac{\partial L}{\partial O}V^\top, \qquad \frac{\partial L}{\partial S} = \mathrm{softmax}\text{ 反向}\!\left(\frac{\partial L}{\partial P}\right) \qquad \text{用 §7.2 的公式}$$

$$\frac{\partial L}{\partial Q} = \frac{\partial L}{\partial S}\frac{K}{\sqrt{d}}, \qquad \frac{\partial L}{\partial K} = \left(\frac{\partial L}{\partial S}\right)^{\!\top}\frac{Q}{\sqrt{d}}$$

**手算会疯的第二个点**：$QK^\top$ 又做一次"跨位置矩阵乘"，$\frac{\partial L}{\partial Q}$ 把每个 query 位置和**所有 key 位置**耦合；$\frac{\partial L}{\partial K}$ 反过来。再叠加多头 × 层数 × batch——每个参数 $W_q$ 的梯度，是几百次矩阵乘和 softmax 迭代出来的。（**多头** = 把 $Q,K,V$ 各切成几份并行算，每份一组注意力、各学各的模式；反向时每头各自回传自己的梯度，再叠回 $W_q,W_k,W_v$。）

### 7.4 为什么你不需要手算，但要会读流向

- **不需要手算**：`F.scaled_dot_product_attention(q,k,v)` 一行，PyTorch 连前向带反向一起给你，而且反向还用了 FlashAttention 的技巧（分段处理，避免把 $N\times N$ 的中间矩阵全留显存，见 04 篇 §4.3）。
- **但要会读流向**：调试/写自定义算子时，你只需要知道"梯度从 $O$ 流回，经过 $V$ 时按 $P^\top$ 收集、经过 $P$ 时先过 softmax 反向、再分别流向 $Q$ 和 $K$"。读懂这句，注意力反向你就通了。

### 7.5 autograd 在这里替你做了多少活

一行 `loss.backward()` 背后，对注意力这一小块：要算 $\frac{\partial L}{\partial O} \to \frac{\partial L}{\partial P} \to \frac{\partial L}{\partial S} \to \frac{\partial L}{\partial Q},\frac{\partial L}{\partial K},\frac{\partial L}{\partial V} \to \frac{\partial L}{\partial W_q},\frac{\partial L}{\partial W_k},\frac{\partial L}{\partial W_v} \to \frac{\partial L}{\partial X}$。全部是 §4.3 那张表里的规则（matmul 转置乘、softmax 去均值）一层层拼起来。**这就是整篇的结论：再复杂的模型，反向也是"一张图 + 每节点一条本地规则 + 逆序走一趟"。**

## 9. 补充材料：特殊函数的梯度怎么算

> 前面 §4.3 的本地规则表里，ReLU 和 max 各占一行。但这两个函数是"**分段 + 带不可导点**"，读者容易卡在"拐点处梯度到底取几"。这里展开讲透，并给出 PyTorch 实测行为。本节按需扩充（sigmoid、tanh 等后续补）。

### 9.1 ReLU：一条折线，梯度是"0/1 门"

**定义（分段函数）**：负数半边压成 0，正数半边原样放行：

$$\mathrm{relu}(x) = \max(0, x) = \begin{cases} x & x > 0\\ 0 & x \le 0 \end{cases}$$

**函数图形**：一条折线——$x\le0$ 时贴住 $x$ 轴（$y=0$），$x>0$ 时是斜率 1 的 45° 直线，两段在 $x=0$ 处撞出个"折点"：

```
relu(x) = max(0, x)

y
4│                        ╱
3│                      ╱
2│                    ╱
1│                  ╱
0│━━━━━━━━━━━━━━━━━╋━━━━━━━━━━━━━━━━━━━▶ x
 │ x≤0：y=0（贴 x 轴）  x>0：y=x（斜率 1）
 │
 -4  -3  -2  -1   0   1   2   3   4
```

**梯度（导数）**：跟着折线分段看——
- $x>0$：$\mathrm{relu}'(x)=1$（45° 直线的斜率）；
- $x<0$：$\mathrm{relu}'(x)=0$（水平线的斜率）；
- $x=0$：**不可导**——左导数 $0$、右导数 $1$，两边不相等。但反向必须给个值，实践中约定取 0（数学上叫"次梯度"），PyTorch 也是这么取的。

统一写法：$\mathrm{relu}'(x)=\mathbf{1}[x>0]$——一个**0/1 门**。

**反向里怎么用**（对应 §4.3 表的"ReLU 门"、§2.2 的步骤 ⑧）：上游梯度 $\times$ 门：

$$\frac{\partial L}{\partial h} = \frac{\partial L}{\partial a}\,\mathbf{1}[h>0]$$

$h>0$ 的神经元：门开，梯度原样通过；$h\le0$ 的神经元：门关，梯度被乘 0、**归零**。

**两个实际后果（读代码时有用）**：
1. ReLU 反向不需要记住 $h$ 的值，只要记"$h$ 是正还是负"一个符号——省显存（PyTorch 存的就是这个 mask）。
2. 如果一个神经元长期收到 $h\le0$，它的梯度永远为 0、参数再不动——这叫**神经元"死"了**（dead ReLU）。初始化、学习率没调好时容易出现。

**验证（PyTorch 2.12.1 实测）**：

```python
import torch
x = torch.tensor([-1., 0., 1.], requires_grad=True)
torch.relu(x).sum().backward()
print(x.grad)   # tensor([0., 0., 1.])  ← relu'(0) = 0
```

### 9.2 max(a, b)：最大者得，其余归零

**定义**：$\max(a,b)$ 取两个数里大的那个 = "if a>b then a else b"。

**梯度（分段）**：
$$\frac{\partial \max(a,b)}{\partial a} = \begin{cases} 1 & a>b\\ 0 & a<b\end{cases}, \qquad \frac{\partial \max(a,b)}{\partial b} = \begin{cases} 0 & a>b\\ 1 & a<b\end{cases}$$

一句话：**最大的那个拿走全部梯度，另一个归零**（winner-take-all）。这正是 §4.3 表"最大者得"、§6.4 MaxPool"只回传给最大元素"的同一规则。

**反向里怎么用（关键是：比大小发生在前向，反向不重新比）**：前向算 $z=\max(a,b)$ 时，顺便记下"**谁赢了**"（一个 0/1 记号：赢家的位置是 1、输家是 0）；反向时 max 节点只收到一个上游梯度 $\frac{\partial L}{\partial z}$，它自己不知道 $a,b$ 谁大——它按前向记下的记号**回放**：赢家 $\times 1$、输家 $\times 0$。

带数字的例子（$z=\max(a,b)$，上游梯度 $\frac{\partial L}{\partial z}=2$）：

| 前向（决定谁赢） | 记下的记号 | 反向（照记号发） |
|---|---|---|
| $a=3,\ b=1.5\ \Rightarrow z=3$（$a$ 赢） | a:1, b:0 | $\frac{\partial L}{\partial a}=2\times1=2,\quad \frac{\partial L}{\partial b}=2\times0=0$ |
| $a=1,\ b=5\ \Rightarrow z=5$（$b$ 赢） | a:0, b:1 | $\frac{\partial L}{\partial a}=0,\quad \frac{\partial L}{\partial b}=2$ |

**和 9.1 其实是同一条规则**：ReLU 就是 $\max(0,x)$——把其中一个数固定成 0。9.1 的"门开/门关" = "和 0 比大小、谁大谁拿梯度"，一个意思。

那"两个数"在真实反向里从哪来？
- **ReLU**：$\max(0,x)$，处处都是（9.1 你已见过）；
- **MaxPool**：窗口里 $k$ 个数比大小（$k=4,9,\dots$，不止两个），规则一样——最大者得、其余全归零（§6.4）；
- **某些损失**：$\max(0,\,1-y\hat{y})$ 这种合页式写法。

**一句总结：前向决定"谁赢"，反向照着"赢家通吃"发梯度。** 前向存的不是 $a,b$ 的数值，而是一个"赢家在哪"的 0/1 记号（PyTorch 存的就是这个 saved mask）。

**边界 $a=b$**：数学上不可导。PyTorch 的取法（实测 2.12.1，属实现细节、不同版本可能不同）：
- `torch.maximum(a, b)`：相等处梯度**平分**（各 $\times 0.5$）；
- `torch.max(x, dim=k)`：并列最大值只给**第一个**。

**验证（PyTorch 2.12.1 实测）**：

```python
import torch
# maximum：相等处平分
a = torch.tensor([2., 1.], requires_grad=True)
b = torch.tensor([2., 3.], requires_grad=True)
torch.maximum(a, b).sum().backward()
print(a.grad)   # tensor([0.5000, 0.0000])  ← 位置0相等，a、b 各拿 0.5
print(b.grad)   # tensor([0.5000, 1.0000])  ← 位置1 b 大，全给 b

# max(x, dim)：并列最大值给第一个
x = torch.tensor([[1., 3., 3., 2.]], requires_grad=True)
torch.max(x, dim=1).values.sum().backward()
print(x.grad)   # tensor([[0., 1., 0., 0.]])  ← 两个 3 只给第一个
```
